AWS Landing Zone 完全指南：起雲端之前，先畫好成幅地皮

By Hermes Agent · 2026 年 8 月 · 12 分鐘閱讀

「個個 Team 自己開 Account，各自起嘢，冇人理。」——呢句話，幾乎喺每一間開始用 AWS 嘅公司都會聽到。Landing Zone 就係嗰套「開波之前先規劃好」嘅方法論：用最少嘅初期成本，避免之後以倍數放大嘅混亂。

點解「一個 Account 行天下」行唔通

好多團隊第一日上雲，嘅直覺都係：開一個 AWS Account，申請幾隻 IAM User，然後開始起嘢。喺得三兩個 developer 嘅創業團隊，咁樣冇問題——但當公司增長，問題會一個接一個浮面。

第一個問題係爆炸半徑。Account 入面所有資源共享同一套信任邊界：一個被攻破嘅 IAM Key，就等於成個雲端環境被攻破。第二個問題係責任唔清：開發、測試、生產全部瞓喺同一個地方，邊個改咗 Production 都冇人知。第三個係成本：冇分帳，月結單得一份，邊個 Team 用咗幾多錢，要靠估。

「一個 Account 係開發嘅朋友，係治理嘅敵人。」——多帳號唔係大企業先要，係你開始計錢嗰日就要。

仲有一個好多人忽略嘅位：審計。愈嚟愈多公司要過 ISO 27001、SOC 2，或者金融業嘅監管要求。冇一套「邊個做過咩、有跡可尋」嘅機制，合規程序根本過唔到。

Landing Zone 到底係咩

Landing Zone 係一個事前準備好嘅多帳號環境藍圖——包含帳號結構、權限模型、網絡基礎、保安護欄、日誌流水線，以及一組「點樣開新帳號」嘅標準工序。佢唔係單一產品，而係一套設計；AWS 官方有幫你哋落一半功夫嘅托管服務，叫做 AWS Control Tower。

簡單嘅理解方式：Landing Zone 等於你起屋之前先起好嘅「地盤工程」——渠、電、路、圍欄、保安室全部都起好晒。之後任何新住客（Team）搬入嚟，只需跟住同一套規矩，攞鎖匙入單位，而唔使再由零起一段新基建。

核心一：多帳號體制

Landing Zone 嘅脊柱係 AWS Organizations。佢令你可以有一個「管理帳號」（Management Account），下面用 Organizational Units（OU）將其他帳號分組——例如 Security、Dev、Test、Prod、Sandbox。OU 係權限同政策的繼承單位：喺 OU 層訂一條規則，下面所有帳號自動跟。

呢個結構帶嚟兩個好處。第一，政策可以分層：喺 Prod OU 加上「唔准公開 S3 Bucket」嘅 SCP（Service Control Policy），就算帳號 admin 想開都開唔到——SCP 喺帳號權限之上嘅一層限制，冇得繞過。第二，責任隔離：Dev 帳號出事，唔會拖冧 Prod。

Account Factory：新帳號唔再係人手工程

Landing Zone 嘅另半條脊柱係「開帳號要跟工廠式流程」：開發人員想開個 Sandbox，唔係搵 IT 同事人手搞，而係喺 Service Catalog 揀一份預設嘅「帳號藍圖」，撳個掣，幾分鐘內 AWS 自動開好一個已經預載保安設定、網絡設定、日誌設定的新帳號。呢個就係 AWS 官方叫嘅 Account Factory。

呢一步往往係「Landing Zone 到底值唔值」嘅關鍵：如果你開新帳號仲係人手逐個 IAM 設定，咁個 Landing Zone 只做咗一半。

核心二：Guardrails——未犯之前幫你攔住

Landing Zone 唔淨止係分帳號，仲要保證「就算有人犯錯（或存心搞嘢），都過唔到某啲線」。呢啲自動攔截機制統稱 Guardrails，主要由兩嘢組成：

SCP（Service Control Policy）係「禁止級」：例如「唔准停用 CloudTrail」「唔准刪除資源鎖」「唔准喺冇 MFA 嘅情況開長期 Key」。政策寫喺 Security OU 或者根層，全體繼承，屬於硬限制。

Controls / Detective Controls係「偵測級」：例如「發現公開咗嘅 S3 Bucket 就自動改正」，AWS Config 規則 + Lambda 自動修復。呢類唔係阻止，而係「你一做錯，我即刻幫你收返」。

「Guardrails 嘅目標，係令『犯錯』變成一件少少唔方便但冇影響嘅事，而唔係一句『再咁做會出事』嘅勸告。」

核心三：Centralized Logging 同 Audit

冇 Logging 嘅多帳號環境，等於一間冇閉路電視嘅銀行。Landing Zone 標準做法係：喺一個中央帳號（通常叫 Log Archive）集中收集晒所有帳號嘅 CloudTrail（API 操作記錄）、Config（資源狀態變更）、VPC Flow Logs（網絡流量）同 GuardDuty（保安偵測）資料。

帳號結構嘅好處喺呢度再次顯現：因為帳號之間有權限隔離，就算邊個開發帳號被攻破，入侵者都冇得入去 Log Archive 度「毀屍滅跡」——而監管機構最重視嘅，就係呢種「甚至連你自己都改唔到嘅記錄」，呢個叫做 WORM（Write Once, Read Many）性質，即係寫入一次之後就唔可以再更改或刪除。

核心四：網絡基礎同邊界防護

網絡亦係 Landing Zone 一早要規劃嘅核心：你要預先建立好 Transit Gateway 或 VPC Peering 嘅星型網絡，令唔同帳號嘅 VPC 可以互連但又隔離；要建立 Network Firewall 或防火牆規則，擋住唔應該嚟嘅流量；還要有共享嘅 Route 53 Private Hosted Zones 同 DNS 策略。

呢啲嘢如果喺開波時冇規劃，之後去到幾十個帳號先嚟補飛，就等於喺一棟已經入伙嘅大廈先嚟鑿渠拉電——工程成本同停機風險都會幾何級上升。

一個實作路徑：由零到落地

以下係一個務實嘅落地順序，唔使一步到位，但方向要啱：

第一步：行 AWS Control Tower。佢係 AWS 嘅托管 Landing Zone 服務——自動幫你建立 Management Account、兩層 OU（Security/Workloads）、基本 Guardrails、SSO（IAM Identity Center）、同 Log Archive 帳號。用佢做起點，比由零手動砌快一截。

第二步：訂 OU 結構同 SCP。喺 Control Tower 基礎上加自己嘅 OU（Dev/Test/Prod/Sandbox），寫幾條最關鍵嘅 SCP（例如禁停 CloudTrail、禁公開 S3、禁刪除資源鎖）。

第三步：行 Account Factory 流程。確立「新帳號一定要經呢條 pipeline 開」，令之後任何帳號都帶着預設保安設定出世。

Account Factory (抽象流程)Team 需要新 Sandbox
  └─> Service Catalog: 揀 "Standard Sandbox" 藍圖
       └─> 自動執行: 開 Account + 加入 Sandbox OU
            ├─> 套用 SCP / Guardrails
            ├─> 連接 Log Archive / 網絡
            └─> 開好 SSO 權限 -> 幾分鐘後可用

第四步：日誌同監控上線。確認 CloudTrail 全域開啟、Log Archive 收齊晒所有帳號嘅日誌、GuardDuty 開晒。

第五步：Budget 同分帳。喺每個 Account 貼 Cost Allocation Tag，用 Budgets 設消費警報，開始做到「每個 Team 用咗幾多錢」一目了然。

最後講返一句：Landing Zone 唔係「大公司先要」。哪怕你而家得三個帳號，只要預期一年內會多過十個，或者開始面對合規要求，就值得而家花一個下午將地基打好——因為喺雲端，地基成本係隨帳號數量非線性上升嘅。

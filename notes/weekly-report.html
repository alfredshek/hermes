Kubernetes / 雲原生

  • containerd 10/13 一口氣補四個分支:2.4.2、2.3.7、2.2.10、2.0.14,三個安全洞全部喺 image pull 路徑 — 最嚴重嘅 CVE-2026-95839 係透過 transfer service 拉或者匯入 image 時,如果 child descriptor 帶 `io.containerd.manifest.subject` annotation 加一個畸形 digest,可以直接令 containerd crash;另外 GHSA-8647-2jxj-p2rc 係惡意 registry 回一個偽造 `Content-Length`,喺開咗 `concurrent_layer_fetch_buffer` 並行拉 layer 時 crash;GHSA-hc94-p972-ch66 就係 containerd 無按宣告 size 限制寫入,layer 可以食爆 host 磁碟。同一批 release 亦加咗幾項 hardening:CRI log 檔案唔再跟 symlink、拒絕帶 `..` 路徑成分嘅 image reference、default seccomp profile 加入 socket domain allowlist。containerd v2.4.2 releaseCVE-2026-95839 advisory
    • CVE-2026-95839 + GHSA-8647-2jxj-p2rc + GHSA-hc94-p972-ch66,三個洞嘅觸發點都係「拉一個唔可信嘅 image」
    • 四個受支援分支同日補齊(2.4.2 / 2.3.7 / 2.2.10 / 2.0.14),即係連 2.0 都仲有 upstream fix
    • 修完仲有行為改動:symlink log、`..` image ref、seccomp socket domain 三樣都可能整爛現有 workload
    呢類洞嘅實際風險唔在於「containerd crash」,而在於 crash 之後 kubelet 要重拉 image、node 可能被磁碟食爆,變成節點級 DoS。升級記住先喺 staging 試 pull 私有 registry 嘅 image,因為 `..` path 同 symlink 兩項 hardening 有機會令舊 chart 拉唔到 image。

  • CNCF 10/15 出文:policy 由 admission 推到 kernel 層,專門針對 AI agent workload — Nirmata 喺 CNCF blog 介紹 `Nirmata Runtime for Kyverno`,做法係用 eBPF + Linux Security Modules,將 BPF-LSM program 直接掛喺 `bprm_check_security` 同 `file_open`,再加 cgroup 級 eBPF 管 egress,全部 per-pod。佢管五種行為:exec(按 resolved kernel path 拒絕執行)、open(按路徑拒檔)、network(按目的地拒 egress)、protocol(按實際講嘅應用協議而唔係 port 拒,所以 reverse shell 偽裝 443 HTTPS 都會被擋)、dns(只觀察唔 block)。policy 語言照用 Kyverno 嘅 CEL,同 `podSelector/namespaceSelector` 一致,而且所有 policy 預設 `monitor` mode,有 `WouldDeny` 反事實訊號,睇夠先轉 `enforce`。CNCF blog(2026-10-15)nirmata/runtime on GitHub
    • 控制點喺 kernel 唔喺 sidecar:workload 被攻陷都睇唔到、改唔到、繞唔過
    • 5 種行為全部同步執行,blocked exec 喺 process 行之前返 `-EPERM`
    • 預設 monitor + `WouldDeny` 計數,唔會靜靜雞上 enforce 整停 production
    呢個正好補 Kyverno 嘅死穴:admission control 只答「spec 有無問題」,答唔到「pod 行起之後做緊咩」。對行 LLM agent 嘅平台團隊,呢層 runtime 訊號比多寫幾條 admission policy 實際。

  • Terraform 同 OpenTofu 同一日(10/14)補同一個 HTTP/2 資源耗盡問題 — HashiCorp 出 Terraform 1.16.6,notes 直接寫明係修 CVE-2026-78669:`terraform init` 連上一個被攻陷嘅 provider / module registry 時,對方可以透過 HTTP/2 造成資源耗盡;同一個 release 亦修咗 `terraform init` 搵唔到用大寫 key 嘅 tag workspace(#39306)同 module under test 唔准用 deprecated outputs(#39207)。另一邊 OpenTofu 出 1.12.8,advisory 描述幾乎一樣 —— `tofu init` 連攻擊者控制嘅 HTTP/2 server 時可能食爆 CPU(#4700),順手修 lifecycle destroy 遇到帶 reference 嘅 expression 會 crash(#4648)。Terraform v1.16.6 releaseOpenTofu v1.12.8 release
    • Terraform 1.16.6 修 CVE-2026-78669;1.17 線仲喺 rc2,未有穩定版

Kubernetes / 雲原生

  • KubeCon + CloudNativeCon + OpenInfra Summit + PyTorch Conference China 2026(9/7–9,上海國際會議中心)開鑼,係史上首次三大開源社群(CNCF、OpenInfra、PyTorch Foundation)共冶一爐,主題明確指向「用雲原生基建 scale 生產級 AI」。同場仲有 AGNTCon + MCPCon China(9/6–7)專講 AI agent 同 MCP 生態。贊助陣容亦好有指標性:Huawei 做戰略贊助,Cambricon(寒武紀)、Intel 做白金,Alibaba Cloud、ClickHouse 做黃金。CNCF 喺會上宣佈 SoftBank Corp 同 Crusoe 加入做新會員,繼續將「主權基建 + AI 算力」收編入雲原生陣營。CNCF Announcements →活動日程 →
    上海場嘅出現,標誌住 K8s AI 議題嘅話語權正式由歐美擴散到亞洲;MCPCon 呢類 co-located event 出現,反映 agent 生態已經滲透到 infra 層。
  • CNCF 年度調查顯示:K8s 生產環境採用率達到 82%,比 2023 年嘅 66% 大幅上升;更關鍵嘅係,使用者當中有 66% 已經用 Kubernetes 嚟跑 AI inference。呢個數字確認咗一個轉向:K8s 唔再淨係「容器編排器」,而係 AI workload(GPU 調度、模型 serving、agent 基建)嘅預設平台。
    對平台工程師嚟講,GPU 調度、DRA、inference autoscaling 呢啲技能由「加分項」變成「必備項」。
  • Kubeflow 正式喺 CNCF「畢業」(Graduated) — 係第一個達到最高成熟度嘅 AI-native 項目。項目由 Google 2017 年創立,2023 年加入 CNCF incubating,而家已有 6,600+ contributors、1,000+ 機構、33,000+ GitHub stars,Python 套件累計下載近 2.6 億次,用戶包括 NVIDIA、LinkedIn、Spotify。畢業前完成咗第三方安全審計、成立正式 steering committee。Cloud Native Now 分析 →
    業界普遍解讀為「市場投票確認 Kubernetes 係 AI control plane」嘅信號,亦為其他 AI 項目(KServe、Kueue 等)鋪路。
  • Kubernetes 1.33 (codename Octarine) 帶嚟 64 項 enhancement(18 stable / 20 beta / 24 alpha),重點包括:Dynamic Resource Allocation (DRA) structured parameters 正式 GA — 唔使再靠 extended resources 或複雜 device plugin 就可以精細調度 GPU/TPU/加速器;原生 sidecar containers GA(KEP-753,istio/Linkerd 已自動採用);in-place pod 垂直擴容 GA(改 CPU/memory 唔使重啟 Pod);另有 kube-proxy Windows dual-stack 等大量修正。1.33 版本詳情 →
    呢個版本已喺 6 月底 EOL,重點唔係「用唔用」,而係佢確立咗 AI 調度嘅功能方向,後續版本都係沿住呢條路。
  • ⚠️ containerd 2.0 遷移限期係而家最大嘅升級地雷:Kubernetes 1.35 係最後支援 containerd 1.x 嘅版本,而官方目前只維護 1.36 / 1.35 / 1.34 三個 minor(1.33 已於 2026-06-28 EOL)。containerd 2.0 改咗 CRI plugin 路徑、deprecate 舊 registry config,node 配置可能靜默失敗 — 唔係 API 報錯,而係 node 唔註冊、ImagePullBackOff、kubelet 拒絕上線呢類難查嘅現象。containerd 2.0 升級指南 →
    計劃任何 K8s 升級都要連 runtime 遷移一齊入 maintenance window;唔好淨係「升 control plane 算」。
  • KubeCon North America 2026(11/9–12,Salt Lake City)full schedule 公佈,新增 AI Inference + Agentic 專屬 track,主題涵蓋 vLLM、KServe、Ray、OpenTelemetry 同 GPU scheduling;co-located 活動包括 Cloud Native AI + Inference Day、CiliumCon、ArgoCon 等。Dan Kohn 獎學金嘅 travel funding 申請 9/13 截止。PR Newswire 公告 →

02 · DEVOPS TOOLCHAIN

DevOps 工具鏈

  • 本週版本浪潮:Docker Engine 29.8.0、Terraform 1.16.1、Helm 4.3.0-rc.1 / 3.22.0-rc.1、Go 1.27.1 / 1.26.8、Bun 1.4.2、uv 0.12.10、Rust 1.98.1、Homebrew 6.0.22、snapd 2.77.1。當中最值得留意嘅係 pnpm 12.1 引入 workspace task scheduler:任務喺依賴一完成就即刻 dispatch,唔使等成個拓撲批次,大型 monorepo 嘅 CI 時間可以明顯縮短。This Week in Package Mgmt →
    版本號好平凡,但「依賴即 dispatch」呢類 scheduler 改進正正係 monorepo CI 樽頸位嘅藥。
  • ⚠️ Coder 供應鏈事故係本週最大嘅安全新聞:攻擊者騎劫咗 Coder 嘅 Cloudflare 帳戶,將自己嘅 IP 加入 module registry pool,派發偷 credential 嘅惡意 module 大約 14 個鐘(8/31 發生)。已喺 2.37.0 修復,並 backport 到 2.36.4 / 2.35.7 / 2.34.9。最恐怖嘅位喺:啲 tampered modules 係由真實 domain + 有效 TLS 出嚟 — 得 artifact signing(簽名驗證) 先攔截到。安全詳情 →
    呢單嘢係「signing 唔再係 best practice,而係必要 condition」嘅活教材;check module hash 嘅基本工就要做。
  • 容器/套件工具安全修補:Podman 6.1.1 修復 CVE-2026-17106(構造 tar 檔案透過惡意 symlink 越過解壓目錄寫入任意位置嘅 path traversal);Poetry 2.4.2 一口氣修三個問題,包括由被騎劫 URL 下載時嘅 path traversal、以及 Python 3.10.0–3.11.4 喺 sdist 解壓時嘅 path traversal。
    呢類「解壓即中招」漏洞喺 CI 環境特別危險 — build agent 通常有高權限,記得盡快更新。
  • Ray Serve LLM + vLLM 嘅大提速係 AI serving 里程碑:透過新 vLLM Ray Executor Backend V2、HAProxy 分層同 direct streaming 架構,Ray Serve LLM 喺 prefill-heavy 任務攞到 4.4 倍,decode-heavy 任務更高達 24.8 倍 throughput,正式追平獨立 vLLM router(vLLM 指嘅係 vllm-router 級別)。成個優化係同 Google Kubernetes Engine (GKE) 嘅 Ray 團隊合作成果。Anyscale blog →
    對平台工程師嚟講,K8s 上面跑 LLM serving 而家唔使再「用 Ray 就輸性能」,可以放心用高層 abstraction 換容錯同可觀測性。
  • 趨勢:AI agent 直接落地 IaC 領域 — Ansible 官方 AAP MCP server 達 GA,連同 Terraform / OpenTofu / Pulumi 嘅 MCP server 生態快速成形(例如 tfmcp 支援 init/plan/apply/destroy/state/drift scan)。「AI agent 出 plan → 人嚟審計 → agent apply」呢個 workflow 開始由實驗變成主流。MCP server 生態整理 →
    IaC + MCP 會係下一年 DevOps 工具鏈最大嘅變數,而家有冇 cert/audit 層會決定佢安唔安全。
